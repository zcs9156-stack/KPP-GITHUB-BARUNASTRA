Sejarah Git dan GitHub

1. Latar Belakang Git

Git dibuat oleh Linus Torvalds pada tahun 2005 untuk mendukung pengembangan kernel Linux. Git dirancang sebagai sistem version control terdistribusi yang cepat dan mampu menangani proyek dengan banyak kontributor.

Dengan Git, setiap pengembang dapat memiliki salinan repository beserta riwayat perubahan. Pengembangan bisa dilakukan secara lokal sebelum perubahan dibagikan kepada pengembang lain.

2. Lahirnya GitHub

GitHub diluncurkan pada tahun 2008 sebagai layanan hosting repository Git. Platform ini memudahkan pengembang untuk menyimpan kode secara daring, bekerja bersama, meninjau perubahan, dan mengelola proyek.

Git dan GitHub memiliki fungsi berbeda:

Git adalah perangkat lunak version control.

GitHub adalah platform kolaborasi dan hosting repository yang menggunakan Git.

Git tetap bisa digunakan tanpa GitHub, misalnya untuk mengelola proyek yang hanya tersimpan di komputer lokal.

3. Perkembangan Fitur GitHub

Seiring perkembangannya, GitHub menyediakan berbagai fitur untuk mendukung kolaborasi, antara lain:

Pull Request: mengajukan perubahan agar dapat ditinjau dan digabungkan.

Issues: mencatat masalah, ide, dan pekerjaan yang perlu dilakukan.

Projects: membantu mengatur dan memantau pekerjaan proyek.

GitHub Actions: mengotomatisasi alur kerja seperti pengujian dan deployment.

GitHub Pages: menerbitkan situs web statis dari repository.

Discussions: menyediakan ruang diskusi untuk komunitas proyek.

Ketersediaan dan konfigurasi fitur dapat berbeda bergantung pada jenis repository dan pengaturan akun.

4. Akuisisi GitHub oleh Microsoft

Pada tahun 2018, Microsoft mengumumkan akuisisi GitHub. Setelah akuisisi tersebut, GitHub terus dikembangkan sebagai platform bagi pengembang individu, komunitas, dan organisasi.

5. GitHub dalam Pengembangan Perangkat Lunak

GitHub digunakan dalam berbagai aktivitas, seperti:

Menyimpan source code dan dokumentasi.

Mengembangkan fitur melalui branch.

Meninjau perubahan melalui Pull Request.

Melaporkan bug menggunakan Issues.

Mengotomatisasi pengujian dan proses rilis.

Berkolaborasi dengan kontributor dari berbagai lokasi.

6. Relevansi bagi Mahasiswa dan Tim Robotik

Dalam proyek robotik dan mikrokontroler, GitHub dapat digunakan untuk menyimpan kode firmware, dokumentasi wiring, konfigurasi perangkat, dan catatan pengujian.

Penggunaan Git membantu tim melacak perubahan kode. Branch memungkinkan pengembangan fitur secara terpisah, sedangkan Pull Request dapat digunakan untuk memeriksa perubahan sebelum digabungkan.

File sensitif seperti password, token, private key, dan kredensial perangkat tidak boleh dimasukkan ke repository.

7. Kesimpulan

Git berkembang sebagai alat untuk mengelola perubahan kode, sedangkan GitHub memperluas proses tersebut dengan fasilitas hosting dan kolaborasi. Keduanya menjadi alat penting dalam pengembangan perangkat lunak modern, termasuk proyek embedded system dan robotik.
